## Review profile: lean (read first)

The user started this session with `DEV_TEAM_REVIEW=lean`. This section overrides step 5 where they differ; every other step runs as written.

- **Plan critics at most the standard tier.** Classify the tier in 5a as written, then dispatch at most the `standard` reviewer set: a `complex` plan gets the Acceptance Test Critic and the Design & Architecture Critic, plus the UX Critic and the Parallelization Critic under the standard tier's own conditions. Record it in the Plan Review Summary, for example `Plan tier: complex (lean profile: standard reviewers)`.
- **One revision round.** When a reviewer returns `needs-revision`, revise the plan for its `blocker` issues once and re-run only the reviewers that flagged blockers, once. If a blocker remains, list it under `## Risks & Open Questions` and go on to step 6, which presents it at the approval gate.
- **Test budget.** Write a Gherkin scenario only for behavior the request states or one of its examples shows. Each step's **TEST** line names the step's scenarios and the request rules no scenario covers, and nothing more: no lists of extra edge cases, permutations, resource or memory bounds, signals or injected filesystem failures that the request does not ask for. `/build` holds the implementer to one test per scenario plus one per such rule.
- **Short plan.** Write the sections `/build` reads (header, Goal, Acceptance Criteria as one line each, Slices with their Gherkin and steps, Parallelization, Complexity Classification, Risks & Open Questions, Build Progress) and keep them terse: no Approach stances, Skipped or Pre-PR Quality Gate prose, no Mermaid diagram for a single-wave plan (one line, such as `One wave: slice 1.`), each scenario three to five lines, each step's **IMPLEMENT**, **TEST** and **REFACTOR** one line each, each open question one line. Pass each plan reviewer the plan path, not the plan text: reviewers read it themselves.
- When the plan reaches `/build`, the same profile applies there: one implementer dispatch and one review panel per slice.
